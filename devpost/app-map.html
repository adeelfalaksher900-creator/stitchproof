Stitchproof — app map

A snapshot of how the finished proof of concept fits together (refreshed October 25, 2026, after the real-pattern round). It can drift as the code changes.

What it is

Paste a knitting pattern. The reader turns it into a stitch program, the counter runs every row for every size, and the fixer searches for the smallest edit that makes a broken row add up. AI is used only to translate lines the offline reader can't parse, and its output is parsed again before anything is counted.

One action, end to end: “Proof pattern”

Route through the code (reference route — not toured interactively)

  1. components/ProofWorkspace.tsx → run(): validates length, calls readPattern, then proofProgram, saves the pattern with save().
  2. lib/read.ts → readPattern(): tries parsePattern() (in lib/stitch/parse.ts); only if lines are unread does it POST to app/api/read/route.ts, whose aiRead() (lib/ai/reader.ts) parses the model's notation and retries once with the parser's errors.
  3. lib/stitch/simulate.ts → simulateRow(): walks the ops with the STITCHES uses/makes table (lib/stitch/stitches.ts) and produces each row's status and messages; its Walk carries stitch-marker positions from row to row. lib/stitch/errata.ts → findErrata() then calls findFixes() (lib/stitch/fixes.ts) to rank edits; the page runs it in a Web Worker (lib/stitch/errata.worker.ts) so long patterns don't freeze the tab.

To change this, start here

  • Add a stitch (e.g. m1lp): add it to STITCHES or ALIASES in lib/stitch/stitches.ts; the counter, strip and plain English pick it up.
  • Read a new phrasing offline: readItem() or readRepeatSpec() in lib/stitch/parse.ts, plus a test in tests/unit/stitch.test.ts.
  • Change how fixes are ranked: the delta score and sort at the end of findFixes().
  • Change the AI model or prompt: candidates() in app/api/read/route.ts (Gemini first, then OpenRouter) and SYSTEM_PROMPT in lib/ai/prompt.ts.
  • Read files: openFile() in components/ProofWorkspace.tsx; PDFs go through pdfText() in lib/pdf.ts, in the browser.
  • Add a sample: lib/samples.ts.

A practice to reuse

Decision: the AI's output is text in the same notation the offline reader already parses, not a hidden structure (devpost/spec.md › What Was Simplified and Why).

Evidence: tests/unit/reader.test.ts shows a malformed model answer being caught by the parser and repaired on the second attempt, and a faithful translation of the prose scarf still exposing its 34-vs-33 error.

Reuse it: whenever a model feeds a deterministic system, make it emit something your own validator can check, and send the validator's errors back for one repair attempt.

Run it again

npm install → npm run dev → open http://localhost:3000/proof?sample=beanie&run=1. Tests: npm test, then npm run build && npm run test:e2e.
